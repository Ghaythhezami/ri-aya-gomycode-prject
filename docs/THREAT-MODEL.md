# RI'AYA threat model

One page, API-focused. Scope: `server/` (NestJS 11, Prisma 6, PostgreSQL) as deployed on Vercel (Neon PostgreSQL, Upstash Redis when `REDIS_URL` is set, otherwise the shared `security_state` table) and locally (Docker Postgres and Redis). All data is fictional, but the design assumes real patient data.

## Assets

| Asset                                                                | Why it matters                                               |
| -------------------------------------------------------------------- | ------------------------------------------------------------ |
| Patient records (name, phone, e-mail, date of birth, clinical notes) | Personal and health data; confidentiality is the primary NFR |
| Staff credentials, access JWT, refresh cookie                        | Account takeover gives tenant-wide access                    |
| Appointment and queue integrity                                      | Double bookings or lost check-ins harm care                  |
| Audit log                                                            | Accountability; append-only by DB trigger                    |
| `JWT_ACCESS_SECRET`, `CRON_SECRET`, `DATABASE_URL`                   | Forge sessions, trigger jobs, read all data                  |

## Trust boundaries

1. Internet to Vercel edge to the API function (untrusted input; `trust proxy` = 1 so `req.ip` is the real client).
2. API to PostgreSQL (Neon, TLS). Every clinic query is scoped by `clinicId` from the verified JWT via `TenantContext`.
3. Tenant to tenant (organization and clinic). Enforced in the service layer, not by the database (no row-level security).
4. Staff roles inside a clinic: `@Roles(CAPABILITY_ROLES.*)`; unknown means deny.
5. Vercel Cron to `/api/notifications/reminders/process` and `/api/demo/reset` (shared bearer secret, constant-time compare).
6. API to the Python microservices `riaya-scheduler` and `riaya-comms` (ADR 0003): a 60-second HS256 token per call signed with `SERVICE_JWT_SECRET` (iss, aud per service, exp). The services take the tenant only from the token's `clinic_id`, reject unknown body keys, answer 404 to non-members, and never receive the user's own JWT. A rejected service token surfaces as 503 to the caller (operator problem), not 401. Admin import/reset needs `scope=admin`, which the API only signs from the cron-protected demo reset and the `sync-comms` script.

## Entry points

Authenticated JSON API under `/api` (JWT bearer, HS256 only); anonymous: `auth/login|refresh|forgot-password|reset-password|register|accept-invite`, `public/display/:clinicId`, `public/check-in/:clinicId`, `health`, `docs`; secret-protected cron routes.

## STRIDE

| Threat                 | Vector                            | Mitigation                                                                                                                                                                                                                                                                                                                                                                        | Residual risk                                                                                                                                                                                          |
| ---------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Spoofing               | Credential stuffing, brute force  | Per-route `@RateLimit` (login 10/min, forgot 5, refresh 30, reset 10, register 5), account lockout, argon2id, password max 128 chars                                                                                                                                                                                                                                              | Lockout counters are shared (Redis or the `security_state` table); the per-route rate limiter itself is per instance, so a burst spread over N warm instances gets up to N times the per-minute budget |
| Spoofing               | Forged or `alg: none` JWT         | Verify pinned to HS256, `exp` enforced, production refuses a default or short secret, membership re-checked on every request                                                                                                                                                                                                                                                      | Single shared symmetric secret; rotate on suspicion                                                                                                                                                    |
| Spoofing               | Refresh token theft               | HttpOnly, `Secure` in production, `SameSite=Lax`, path `/api/auth`, rotation with family reuse detection                                                                                                                                                                                                                                                                          | Token stored in the DB as hash only; stolen live cookie works until rotated                                                                                                                            |
| Tampering              | Mass assignment, oversized bodies | Global `ValidationPipe` (whitelist, forbid unknown), length and array caps on every DTO, 256 kb body limit; `clinicId`, `organizationId`, `role` never read from bodies                                                                                                                                                                                                           | Invitation DTO accepts a role and clinic selector; both are checked against the caller's organization and capability                                                                                   |
| Tampering              | Double booking races              | SERIALIZABLE transaction, slot locks, `appointments_no_overlap` exclusion constraint                                                                                                                                                                                                                                                                                              | Slot locks are in-memory per instance without Redis; the DB constraint remains the authority                                                                                                           |
| Repudiation            | Denied clinical edits             | Audit row in the same transaction, append-only trigger, request id on every log line and error body                                                                                                                                                                                                                                                                               | Audit rows are not shipped to external WORM storage                                                                                                                                                    |
| Information disclosure | Cross-tenant reads (IDOR)         | `clinicId` filter or ownership check on every query under clinic, patients, doctors, appointments, queue, scheduling, analytics, notifications, settings, chat; cross-tenant ids return 404; e2e isolation suites                                                                                                                                                                 | No database-level RLS: a missed filter in new code would leak. Review rule in `AGENTS.md`                                                                                                              |
| Information disclosure | Logs and errors                   | pino redaction (authorization, cookie, set-cookie, password, tokens, phone, email, dateOfBirth, clinicalNotes, adminNotes, address), serializers emit id, method, path only (no query string, no bodies); error body is `{ code, message, details, requestId }`; Prisma/driver errors become generic 500 (P2025 to 404, P2002/P2003 to 409) and are logged by class and code only | Stack traces of non-Prisma bugs are in server logs (not in responses)                                                                                                                                  |
| Information disclosure | Probing                           | `/api/health` returns only up/down; helmet with HSTS; CORS allow-list from `CORS_ORIGINS`, wildcard ignored; password reset and login do not reveal account existence                                                                                                                                                                                                             | Public display and check-in expose queue numbers and rooms; the check-in code and last 4 phone digits are guessable in principle, limited to 10/min per IP                                             |
| Denial of service      | Request floods, heavy reports     | Global 60/min plus tight per-route limits, 429 with `Retry-After`, pagination capped at 100, analytics range capped at 366 days and cached 60 s, indexed lookups                                                                                                                                                                                                                  | In-memory limiter is per instance; a distributed flood needs the edge firewall or Vercel WAF rules                                                                                                     |
| Denial of service      | Argon2 CPU abuse                  | Password length cap, login rate limit                                                                                                                                                                                                                                                                                                                                             | Lockout gives an attacker a way to lock a known e-mail for the lockout window                                                                                                                          |
| Elevation of privilege | Role bypass, suspended member     | `RolesGuard` on capability matrix, membership status re-verified on each request, organization scope requires SUPER_ADMIN (checked before cache lookup)                                                                                                                                                                                                                           | Access JWT lives up to 15 minutes, but membership is re-checked so suspension is immediate                                                                                                             |
| Elevation of privilege | Cron routes                       | Secret required, constant-time compare, rate limited, demo reset disabled unless `DEMO_MODE=true`                                                                                                                                                                                                                                                                                 | Shared secret; rotate through Vercel env                                                                                                                                                               |

## Residual-risk summary

1. Rate limiter, slot locks and caches are per instance unless `REDIS_URL` is set; lockout and token revocation are always shared (Redis or PostgreSQL). Set `REDIS_URL` before real clinics.
2. No row-level security; isolation relies on code review and tests.
3. Secrets rotation is manual.

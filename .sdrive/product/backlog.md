# RI'AYA — Product Backlog

> **Status:** Approved (owner approval 2026-10-27)
> **Last Updated:** 2026-10-27
> **Source:** MediFlow brief §6–§10 epics, Ri'aya feature spec parts 1–14, repository discovery

Product-level feature candidates only. **No feature specs, plans, tasks or governance records
exist for these items** — promote one with `/sdrive:propose "<feature description>"`.

**Identifiers:** backlog items use the SpecDrive `BP-###` scheme, which is what
`sdrive dashboard` and `scripts/worktree.js` parse. The original assignment-brief task ID is kept
in the **Brief task** column so every item still traces to a graded acceptance criterion. Two
scopes the brief did not cover were added: **`MT`** (multi-tenancy, from Ri'aya spec part 2) and
**`BIL`** (billing, owner decision), plus **`USR`** (user management, Ri'aya spec part 3).

**Status vocabulary:** `backlog` (not started) · `partial` (some code exists) · `deferred` (parked, not scheduled).
